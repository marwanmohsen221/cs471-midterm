L1

Pipelining Introduction

الفكرة: بدل ما تخلص حاجة وبعدين تبدأ اللي بعدها، ابدأ اللي بعدها قبل ما الأولى تخلص.

Parallel Processing

تنفيذ أحداث متزامنة عشان نسرّع الحساب ونزود الـ throughput (كمية الشغل اللي بتخلص في وقت معين). العيب إن الـ hardware بيزيد فالتكلفة تزيد، بس التكنولوجيا رخّصت الـ hardware فبقى مجدي.

تصنيف Flynn (1966)

بيبص على حاجتين: كام Instruction بتتنفذ في نفس الوقت، وكام Data. أول حرفين للـ instruction وآخر حرفين للـ data.

النوعمعناه ببساطةبيتستخدم في
SISDprocessor واحد، أمر واحد على بيانات واحدة. رخيص وموفر بس بطيء.Microcontrollers، older mainframes، أي single-processor
SIMDcontrol unit واحدة بتبعت نفس الأمر لكذا processor، وكل واحد على بيانات مختلفة.GPUs، scientific processing (مثال تحريك شخصية في لعبة)
MISDأوامر كتير على نفس البيانات. نظري بس، مفيش منه تجاري.Space shuttle flight control (fault detection)
MIMDكل processor بأمر مختلف وبيانات مختلفة. ممتاز للـ multitasking بس أغلى.أغلب الـ PCs واللابتوبات والموبايلات

مثال الغسيل (أهم مثال في المادة)

4 طلاب، كل واحد عنده غسيل: غسالة 30 دقيقة، نشافة 40، طي 20.

  • Sequential: كل واحد يخلص كله وبعدين اللي بعده: 4 × 90 = 360 دقيقة = 6 ساعات.
  • Pipelined: أول ما الأول يطلع من الغسالة التاني يدخل: 30 + (4 × 40) + 20 = 210 دقيقة = 3.5 ساعة.
الدروس المستفادة (بتيجي صح وغلط)
  • أبطأ مرحلة (النشافة 40) هي اللي بتحدد وقت النهاية: slowest stage determines the finish time.
  • الـ task الواحدة مش بتسرع (لسه بتاخد 90 دقيقة). اللي بيسرع هو متوسط الوقت لكل task (210 ÷ 4 = 52.5 دقيقة).
  • Balanced pipeline = كل المراحل نفس الوقت، وده الوضع المثالي. فيه: الـ speedup = عدد المراحل.

مصطلحات

  • Latency: الوقت اللي instruction واحدة بتاخده لحد ما تخلص.
  • Throughput: عدد الـ instructions اللي بتخلص في الثانية.
  • Clock cycle: كل حاجة في الـ CPU بتتحرك مع بعض على نبضة الـ clock.
  • Processor cycle: الوقت اللازم لتحريك instruction خطوة واحدة في الـ pipeline.
  • CPI: متوسط عدد الـ clock cycles لكل instruction.

شكل الـ pipeline من جوه

الـ pipeline مقسوم لـ segments. كل segment دايرة (combinational circuit Si) بتعمل جزء من الشغل، وبين كل segment والتاني register (Ri) بيشيل النتيجة للمرحلة اللي بعدها (زي الشخص اللي بيشيل الهدوم من الغسالة للنشافة). كل الـ registers شغالة على clock واحد مشترك.

القوانين (هتتحل في الامتحان أكيد)

عندك k = عدد الـ segments، و n = عدد الـ tasks، و tp = زمن الـ clock cycle، و tn = زمن الـ task من غير pipeline.

Pipeline cycles = k + (n − 1)
Pipeline time = (k + n − 1) × tp
Non-pipeline time = n × tn    (usually tn = k × tp)
Speedup S = (n × tn) / ((k + n − 1) × tp)

ليه k + n − 1؟ أول task بياخد k cycles عشان يعدي على كل المراحل. بعدها الـ pipeline بيبقى مليان، فكل cycle بيطلع task جديد، يعني الـ (n − 1) الباقيين بياخدوا (n − 1) cycles.

مثال محلول (زي الكويز) k = 4، tp = 10 ns، n = 200:
الوقت = (4 + 200 − 1) × 10 = 2030 ns.
من غير pipeline: tn = 4 × 10 = 40، والوقت = 200 × 40 = 8000 ns.
Speedup = 8000 ÷ 2030 ≈ 3.94.
لازم تحفظ
  • أقصى speedup نظري = k (عدد الـ segments). ده لما n تكون كبيرة جدًا.
  • بعد ما الـ pipeline يتملي، بيطلع output كل clock cycle واحدة مهما كان عدد الـ segments.
  • الـ clock cycle لازم يساوي أبطأ segment. فلو المراحل 30، 45، 25، 40 يبقى الـ clock = 45.
  • ليه مش بنوصل للـ speedup الأقصى؟ المراحل مش متساوية، والسريعة بتستنى البطيئة.
  • نوعين pipeline: Arithmetic pipeline (بيقسم عملية حسابية) و Instruction pipeline (بيداخل fetch و decode و execute).

RISC and Instruction Pipelining

الفكرة: نطبّق الـ pipeline على الـ instructions نفسها جوه الـ CPU، باستخدام RISC لأن أوامره بسيطة ومتساوية الحجم.

Instruction Pipelining

  • تقنية بتنفذ ILP (Instruction Level Parallelism) جوه processor واحد. الـ pipeline اسمه برضه ILP.
  • الـ processor يبقى fully pipelined لو يقدر يعمل fetch لـ instruction جديدة كل cycle.
  • مشروع IBM Stretch (1956–1961) هو اللي سمّى Fetch و Decode و Execute.
  • Atmel AVR و PIC فيهم pipeline من مرحلتين بس.

CISC ضد RISC

فخلو شفت ضرب وجمع في أمر واحد، أو أقواس [ ] (memory) في أمر حسابي، يبقى CISC. و "SISC" و "RISK" اختيارات وهمية.

خصائص RISC

  • كل العمليات على البيانات بتحصل في الـ registers.
  • Load و Store بس هم اللي بيلمسوا الـ memory. Load من الـ memory للـ register، Store العكس.
  • عنده 32 register، والـ instructions كلها نفس الحجم (32 bit)، و formats قليلة.
  • 3 classes من الأوامر: (1) ALU مثل add و sub و and و or، (2) Load/Store والعنوان = base register + offset ويتسمى effective address، (3) Branches/Jumps زي if-else.

الـ 5 Stages (أهم حاجة في المادة كلها)

IFInstruction Fetch: هات الأمر من الـ memory و PC = PC + 4
IDDecode: افهم الأمر واقرا الـ registers
EXExecute: الـ ALU يحسب (أو يحسب الـ effective address)
MEMMemory: load يقرا أو store يكتب
WBWrite Back: اكتب النتيجة في الـ register
  • ليه PC + 4؟ لأن كل instruction = 32 bit، وكل خانة memory = 8 bit، فالأمر بياخد 4 خانات.
  • ADD: مرحلة MEM فاضية (dummy) لأنه مش بيلمس الـ memory.
  • LD R1,24[R0]: EX يحسب R0 + 24، و MEM يقرا، و WB يكتب في R1. كل المراحل شغالة.
  • Branch: العنوان والشرط بيتحسبوا بدري، فالـ branch بيخلص في 2 cycles والباقي مفيهوش شغل.
  • في كل EX فيه 3 حالات: memory reference (يجمع base + offset)، register-register ALU، register-immediate ALU (مع sign-extended immediate).

شكل الـ instructions (R / I / J)

R op6rs5rt5rd5shamt5funct6
I op6rs5rt5immediate / offset16
J op6jump target address26
لازم تحفظ
  • 3 أنواع: R (Register) و I (Immediate) و J (Jump). كلهم يبدأوا بـ 6-bit opcode والمجموع 32.
  • R-type فيه 3 registers (rs, rt, rd) + shamt + funct.
  • I-type فيه 2 registers + 16-bit immediate.
  • J-type = opcode + 26-bit target.
  • كل register field = 5 bits، لأن 2⁵ = 32 register.
  • rs = أول source، rt = تاني source، rd = destination.

إزاي الـ pipeline بيشتغل فعلًا

  • بنبدأ instruction جديدة كل cycle، فالـ speedup المثالي = 5.
  • لازم instruction memory منفصلة عن data memory، لأن IF و MEM بيستخدموا الـ memory في نفس الـ cycle. لو memory واحدة يحصل تعارض.
  • بين كل مرحلة والتانية pipeline register: IF/ID، ID/EX، EX/MEM، MEM/WB. اسم الـ register = المرحلتين اللي هو بينهم.
  • في cycle 5 الـ pipeline بيبقى مليان وكل الـ hardware شغال.
مثال المحاضرة (كل register = رقمه + 100، وكل memory = 99) lw $8, 4($29): العنوان = 129 + 4 = 133، والقيمة اللي هتتقري = 99، فـ $8 = 99.
sub $2, $4, $5 = 104 − 105 = −1.
L3

Performance Equations and Pipeline Hazards

الفكرة: نحسب سرعة الـ CPU بالأرقام، وبعدين نشوف إيه اللي بيعطّل الـ pipeline وإزاي نحله.

معادلات الأداء

CPU time = IC × CPI × Clock cycle time
CPI = CPU clock cycles / IC
Average CPI = Σ (ICi / IC) × CPIi
Avg instruction time = Clock cycle × Avg CPI

IC = عدد الـ instructions. و Average CPI = متوسط مرجّح: نسبة كل نوع instruction × عدد cycles بتاعه.

مثال المحاضرة (لازم تعرف تحله) Clock = 1 ns. ALU 40% و branch 20% بياخدوا 4 cycles، و memory 40% بياخد 5 cycles. Overhead = 0.2 ns.
1) من غير pipeline: 1 × [(0.4 + 0.2) × 4 + 0.4 × 5] = 4.4 ns
2) بالـ pipeline: الـ ideal CPI = 1، يعني 1 × 1 + 0.2 = 1.2 ns
3) Speedup = 4.4 ÷ 1.2 ≈ 3.7

الـ Hazards: يعني إيه؟

Hazard = حالة بتمنع الـ instruction الجاية إنها تتنفذ في الـ cycle بتاعها. فيه 3 أنواع، احفظهم بالسبب:

النوعالسببمثال بسيطالحل
Structuralتعارض على resource (الـ hardware مش كفاية)memory واحدة و IF و MEM عايزينها في نفس الوقتstall، أو زوّد الـ resources (separate instruction & data cache)
Datadata dependency: أمر محتاج نتيجة أمر لسه مخلصشADD R1,... وبعده SUB ...,R1,...stall، أو Forwarding، أو Out-of-order (Tomasulo)
Controlتغيير الـ PC (branches)beq، مش عارفين نجيب أنهي أمر بعدهstall + flush، delay slot، predict (محاضرة 4)

التعريف الرسمي للـ Data Hazard (جه في الكويز): "occur when the pipeline changes the order of read/write accesses to operands so that the order differs from the order seen by sequentially executing instructions on an unpipelined processor".

الـ Stall (Bubble)

  • الـ stall = نوقف instruction cycle أو أكتر. اسمه برضه bubble.
  • لما instruction توقف، كل اللي بعدها بيوقف، و اللي قبلها بيكمل (وإلا الـ hazard عمره ما هيتحل). ومفيش fetch لأوامر جديدة.
CPI pipelined = 1 + stalls per instruction
Speedup = CPI unpipelined / (1 + stalls per instruction)

مثال الـ Data Hazard

Instruction123456hazard?
ADD R1,R2,R3IFIDEXMEMWBwrites R1
SUB R4,R1,R5IFIDEXMEMWBYES (distance 1)
AND R6,R1,R7IFIDEXMEMYES (distance 2)
OR R8,R1,R9IFIDEXNO (distance 3)

ليه OR مفيهاش hazard؟ الـ ADD بيكتب R1 في النص الأول من cycle 5، والـ OR بيقرا R1 في النص التاني من نفس الـ cycle. فبيلحق.

قاعدة ذهبية للمسافة بين الأمرين
  • المسافة 1 (ورا بعض على طول): hazard، والحل forwarding من EX/MEM.
  • المسافة 2: hazard، والحل forwarding من MEM/WB.
  • المسافة 3 أو أكتر: مفيش hazard.

الحل بالـ stall بس (من غير forwarding): الـ SUB بتستنى 2 stalls، وكل اللي وراها بيتأخر معاها. الـ 5 أوامر كانوا هياخدوا 9 cycles، بقوا 11.

الـ Forwarding (Bypassing)

بدل ما نستنى النتيجة تتكتب في الـ register file ونقراها تاني، ناخدها على طول من الـ pipeline register (EX/MEM أو MEM/WB) ونوديها لمدخل الـ ALU. ده بيعمله forwarding unit و 2 multiplexers قدام الـ ALU:

القيمةالمعنى
0مفيش hazard، خد من الـ register file عادي
1خد من MEM/WB (المسافة 2)
2خد من EX/MEM (المسافة 1)

ForwardA = للـ operand الأول (Rs)، و ForwardB = للـ operand التاني (Rt).

شرط EX/MEM hazard: الأمر اللي قبلي بيكتب في register (EX/MEM.RegWrite = 1)، والـ destination بتاعه = واحد من الـ sources بتوعي:

if (EX/MEM.RegWrite = 1 and EX/MEM.RegisterRd = ID/EX.RegisterRs) → ForwardA = 2

شرط MEM/WB hazard: نفس الفكرة بس من MEM/WB، بشرط زيادة: إن EX/MEM مش بيكتب في نفس الـ register (عشان لو الـ register اتكتب مرتين ورا بعض، ناخد الأحدث من EX/MEM).

if (MEM/WB.RegWrite = 1 and MEM/WB.RegisterRd = ID/EX.RegisterRs and (EX/MEM.RegisterRd ≠ ID/EX.RegisterRs or EX/MEM.RegWrite = 0)) → ForwardA = 1
إزاي تحل سؤال hazard في الامتحان (خطوات)
  • ارسم الجدول: كل أمر يبدأ بعد اللي قبله بـ cycle: IF ID EX MEM WB.
  • لكل أمر، شوف الـ sources بتوعه (آخر 2 registers). هل أي أمر قبله كتب فيهم؟
  • احسب المسافة: 1 يبقى EX/MEM، و 2 يبقى MEM/WB، و 3 مفيش.
  • الـ hazard بيتكشف لما الأمر المحتاج يوصل EX. مثلًا أمر 2 بيدخل EX في cycle 4 (ودي إجابة الكويز).
مثال الكويز: ADD R1,R3,R3 ثم SUB R1,R1,R5 ثم AND R6,R8,R1 ثم OR R8,R11,R1
• أول hazard في cycle 4.
• hazard الـ SUB من EX/MEM.
• AND فيها hazard؟ True (R1 من SUB، المسافة 1).

لما الـ Forwarding مش بيكفي: Load

LD R1, 0(R2) وبعده SUB R4, R1, R5: الـ load بيجيب R1 من الـ memory في MEM (آخر cycle 4)، والـ SUB محتاجاه في أول cycle 4. مينفعش نبعت data لورا في الزمن (forwarding cannot be backward)، فلازم stall واحد وبعده forwarding من MEM/WB.

L4

Data Hazard Stalls and Control Hazards

الفكرة: إزاي نعمل الـ stall فعليًا لما الـ forwarding ميكفيش، وإيه نعمل مع الـ branches.

نوعين data hazards

  • Potential: الـ forwarding unit بيحلها من غير ما يأثر على الأداء.
  • Unavoidable: الـ forwarding مش قادر عليها (زي الـ load-use). محتاجين hazard detection unit يعمل stall.
Instruction1234567
LW $s0,100($t0)IFIDEXMEMWB
ADD $t2,$s0,$t3IFIDstallEXMEMWB

إزاي نعمل الـ stall؟ طريقتين

  • #1 بالـ Compiler: الـ compiler يكتشف ويحط NOP (أمر مبيعملش حاجة: SLL $0, $0, 0). العيب: بنعتمد على الـ compiler.
  • #2 بالـ Hardware: hazard detection unit في مرحلة ID. بيعمل stall لو الأمر اللي في EX هو load (ID/EX.MemRead = 1) والـ register اللي بيحمّله (RT) هو واحد من اللي الأمر الحالي محتاجه:
if (ID/EX.MemRead = 1 and (ID/EX.RegRT = IF/ID.RegRS or ID/EX.RegRT = IF/ID.RegRT)) → stall

تأثير الـ stall: مرحلة ID بتتكرر (IF ID ID EX ...)، عن طريق إننا نحافظ على قيم IF/ID للـ cycle الجاية. وبعدها MEM/WB forwarding.

الـ Control Hazard (الـ branches)

المشكلة: الأمر بيتجاب في IF (stage 1)، لكن قرار الـ branch (نروح ولا لأ) بيتعرف في EX (stage 3). فإحنا بنجيب أوامر وإحنا مش عارفين هي صح ولا غلط.

AddressInstruction123456
10beq r1, r2, LIFIDEXMW
14add r3, r0, r3IFIDNOPNOPNOP
18sub r5, r4, r6IFNOPNOPNOP
25L: or r3, r2, r4IFIDEx

لو الـ branch اتاخد (taken)، الأوامر اللي اتجابت غلط بنعملها Zap / Flush: نمسح IF/ID ونحوّلها NOP، ونمنع تحديث الـ PC.

إزاي نقلل خسارة الـ branch؟

  • ننقل قرار الـ branch من EX لـ ID: (أ) حساب الـ target address، (ب) قرار الشرط. الـ penalty بيقل من 3 cycles لـ 1 cycle. بس محتاج bypasses جديدة للـ ID.
  • Delay slot: الأمر اللي بعد الـ branch بيتنفذ دايمًا سواء الـ branch اتاخد ولا لأ. MIPS عنده 1 delay slot. الـ compiler يحط فيه أمر مفيد، ولو مقدرش يحط NOP.
الـ 3 حلول للـ Control Hazard (سؤال مضمون)
  • Stall: وقّف الـ fetch لحد ما النتيجة تبان. خسارة كبيرة، ومحتاج hardware للـ stall.
  • Delayed branch: الأمر اللي بعد الـ branch بيتنفذ دايمًا. الـ compiler بيرتب، ويحط NOP لما ميقدرش (حوالي 50%). ده اللي original MIPS كان بيعمله.
  • Predict: خمّن وكمّل، ولو طلع غلط الغي (squash). الخسارة بس لما التخمين يغلط.

كل القوانين في مكان واحد

القانونبيتستخدم إمتى
cycles = k + n − 1عدد الـ cycles لـ n tasks على k segments
time = (k + n − 1) × tpوقت الـ pipeline
non-pipe = n × tn, tn = k × tpوقت من غير pipeline
S = n·tn / ((k+n−1)·tp)الـ speedup، وأقصاه k
CPU time = IC × CPI × clockوقت تشغيل البرنامج
Avg CPI = Σ (fraction × CPIi)لما يديك نسب الأوامر
pipelined time = 1 × clock + overheadمتوسط وقت الأمر بالـ pipeline
S = unpipelined time / pipelined timeمثال 4.4 / 1.2
CPI pipe = 1 + stalls/instrلما فيه stalls
S = CPI unpipe / (1 + stalls)لما الـ clock واحد في الحالتين
وحدات1 GHz يعني clock = 1 ns. و 10⁶ ns = 1 ms. و 10⁹ ns = 1 s.
